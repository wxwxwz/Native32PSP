# 游戏循环与画面准备优化

本轮根据已有 PSP 日志减少游戏运行中的像素扫描、临时内存分配和画面准备开销，并修复固定跳帧在连续追帧时可能不再出画面的问题。设备日志来自改动前的构建；本轮尚无 PSP 真机结果，主机耗时不能换算为实际帧率。这些改动仍归入 Unreleased，不改变版本号。

## 改动前的设备证据

开发工作区保存了从设备复制的 `tmp/game-smooth-device-before.log`，日志标识为 `1.3.0 20260919.2224`。设备 PBP 的 SHA-256 前缀为 `5b2b87`，用于区分这份基线与后续构建；日志和游戏文件不随源码、运行包分发。

`STPLAY10.SSL` 的最后一次运行包含 69–73 个精灵。剔除含场景加载的首个统计窗口后，后续四个窗口显示：

| 项目 | 改动前记录 |
| --- | --- |
| `logic_us` 窗口平均 | 17.540–20.908 ms |
| `logic_us` 窗口最大 | 44.248–53.946 ms |
| `prepare_us` 窗口平均 | 6.650–6.652 ms |
| `transfer_us` 窗口平均 | 1.345–1.364 ms |
| 呈现与设置 | 320×240，GE-copy，sharp，AUTO，render_period 2 或 3 |

这些是统计窗口的平均值和最大值，不是完整逐帧轨迹。`logic_us` 包含核心运行及需要时的合成，不能据此把全部耗时归因于脚本；`prepare_us` 与 `transfer_us` 则分别显示画面准备和 GU/GE 提交同步成本。日志中的音频欠载计数是累计值，也不能直接当作每个窗口新增的欠载数。

## 核心合成

已解码图像和自有精灵替换图像在缓存建立时记录 alpha 非零像素的包围盒。绘制时把它与画布裁剪范围相交，跳过图像四周透明区域；包围盒内仍逐像素检查透明洞。缓存逐出并重新解码时重新计算元数据，外部可修改图像的公开 `blitImage` 接口仍使用普通检查。

透明规则保持为 alpha 为零不覆盖，任何非零 alpha 直接替换目标，不新增半透明混合。只有排序后的首个有效绘制层数据完整、所有像素 alpha 非零、覆盖整张画布，且目标缓冲长度与画布一致时，才省略该帧的黑色清空。截断图像、透明洞、部分覆盖、空场景等情况继续清空，防止上一帧残留。精灵深度与同深度绘制顺序保持原样。

## 精灵与时间轴

`SpriteSystem::updateForFrame` 使用精灵状态中的临时成员标记本帧是否存在，替代逐帧创建的名称集合与删除列表。每次更新先重建标记；精确名称优先，改名后仍按原 map 顺序选择首个 movie 与 depth 相同的非克隆精灵，保留重复对象和克隆的原有处理方式。

`Emulator::processMovieFrames` 复用拥有字符串内容的名称快照，保留长名称的容量，并只遍历本次快照的有效数量。脚本删除、改名或克隆精灵时，遍历仍依赖独立名称快照；新增名称不会凭空加入本轮快照。重置、加载尝试以及成功的内容切换会释放快照存储。场景临时扩张后，容量可保留到下一次重置或加载。

`TotalFrames` 直接读取已缓存的电影帧向量，省去查询时复制整个向量。以上优化的零分配目标仅针对缓存及名称容量预热后的稳定路径；新精灵、名称增长、资源首次读取和脚本自身仍可能分配内存。

## 画面准备、缓存与追帧

ARGB 到 ABGR 的转换改用字节反转与旋转，并将行宽、行数及指针保存在循环局部变量中。PSP 目标反汇编已确认使用 `WSBW` 与 `ROR`，减少逐像素的移位、掩码及重复取成员操作。输出格式、alpha 和所有颜色位保持一致，缩放与滤波规则沿用现有呈现路径。

GU/GE 绘制前仍发布源缓冲，并写回、失效目标页的 CPU 缓存；绘制完成后仍等待同步。移除的是同步后重复进行的整张画布写回。FPS 与截图通知等后续 CPU 写入继续按各自区域写回，双显示页、背景黑边和截图仍需要按原有顺序处理。

固定跳一帧在正常单 tick 节奏下继续每两次逻辑 tick 绘制一次。若一次需要追赶两个 tick，前一个 tick 已不合成，最后一个 tick 会获得绘制机会，避免其奇偶性始终落在被丢弃的一侧。逻辑、脚本和音频仍逐 tick 推进。

## 回归与基准

PSPSDK 全新目录全量构建已通过，构建日志无 warning/error；普通核心渲染回归及其 ASan/UBSan 检查已通过。当前 PBP 的 SHA-256 为 `4462ce8753685af6de187f1742067a3547bd43352d816061b81060782c9f7b2c`，这标识本轮构建产物，不表示已经发布或经过真机验证。

颜色转换已通过覆盖全部颜色及 alpha 位、各位补码和随机组合的 4096 像素用例，以及原尺寸、纹理呈现回归。PSP 指令检查确认了转换序列。完整普通 AV 回归及 `SANITIZE=1 sh tests/run-av.sh` 已全部通过，包含新固定跳帧、缓存调用和游戏循环用例。PBP 结构、标题、图标与远端 SHA-256 一致性检查也已通过。

本轮测试覆盖：

- 独立逐像素参考下的透明边界、内部透明洞、屏外位置、极端坐标、截断存储、背景覆盖与缓存逐出后重建。
- 独立旧名称集合算法与 1000 轮精灵增删、改名、克隆、重名及重复帧对象对照。
- 真实 ActionVM 在电影帧遍历中自改名、删除同伴、同伴改名和克隆；与独立拥有名称的旧快照算法比较。
- 精灵数量减少后的快照有效数量，以及 reset、失败或成功加载、SSL 场景切换时释放容量。
- 128 个长名称精灵连续 2000 次稳定更新时间轴、电影帧快照和 TotalFrames 查询的分配次数与耗时。
- 固定跳帧的两个追帧奇偶相位、逻辑与音频总量，以及正常节奏下的 15 次/秒绘制安排。
- GE-copy 与 GU-texture、双显示页、首次清空和稳定帧、FPS 与截图通知组合下的像素结果及缓存调用顺序。

在开发目录 `psp/native32psp` 或独立公开仓库根目录执行：

```sh
sh tests/run-host.sh
sh tests/run-game-loop.sh
sh tests/run-av.sh
sh tests/run-mp3.sh
SANITIZE=1 sh tests/run-host.sh
SANITIZE=1 sh tests/run-game-loop.sh
SANITIZE=1 sh tests/run-av.sh
```

`run-av.sh` 已包含游戏循环回归，`run-game-loop.sh` 可单独运行。该测试使用合成数据，独立旧实现与新实现运行于同一进程；ASan/UBSan 构建关闭全局分配替身，检查内存访问与未定义行为。

普通构建预热后，128 个长名称精灵的稳定循环测得以下分配次数；每项均执行 2000 次，功能及状态与独立旧实现一致。

| 项目 | 旧实现分配次数 | 新实现分配次数 |
| --- | ---: | ---: |
| 时间轴成员更新 | 512000 | 0 |
| 电影帧名称快照及推进 | 258000 | 0 |
| 已缓存电影的 TotalFrames 查询 | 2000 | 0 |

这里只报告可确定的分配次数，不将单次游戏循环计时作为速度收益；TotalFrames 旧参考省略了精灵查找，也不适合直接比较耗时。以下渲染与画面准备的正式基准同时比对输出摘要。
同一主机、相同 `g++ -O3` 配置下，改动前后交替运行各 7 次，取耗时中位数。表中单位为微秒，均为指定次数的总耗时，不是单帧耗时。

| 项目 | 次数 | 改动前 | 改动后 | 耗时变化 |
| --- | ---: | ---: | ---: | ---: |
| 32 个移动稀疏精灵与完整背景 | 1500 帧 | 209997 | 60196 | -71.33% |
| 32 个移动混合精灵与完整背景 | 1500 帧 | 161941 | 63909 | -60.54% |
| 原 128 个不透明 16×16 精灵场景 | 3000 帧 | 202276 | 207438 | +2.55% |
| 320×240 画面准备：原尺寸 | 3000 次 | 149947 | 140661 | -6.19% |
| 320×240 画面准备：保持比例 | 3000 次 | 159183 | 154812 | -2.75% |
| 320×240 画面准备：铺满屏幕 | 3000 次 | 161786 | 159716 | -1.28% |

稀疏和混合场景的每帧像素均计入摘要，改动前后分别保持 `89ce791ae284069a`、`41dd8515f1cadab7`，稳定合成均为零分配。原核心摘要仍为 `8d63a40ac08ec6b1`。原不透明小精灵场景没有大块透明边缘可跳过，本次主机中位数约增加 1.7 微秒/帧，不能据此宣称所有场景都变快。

画面准备三种模式的输出摘要也分别一致；这组只测 CPU 准备，不计真实 PSP GU/GE 传输。PSP 的 `WSBW`/`ROR` 指令变化与主机耗时属于不同证据，主机收益比例不能直接套到 PSP。详细记录位于开发工作区的 `tmp/game-smooth-render-benchmark.log` 与 `tmp/game-smooth-presentation-benchmark.log`。


## 真机验证

本轮尚未取得真机验证结果。后续应记录新 PBP 的构建时间与哈希，在相同 PSP、游戏场景和设置下对比 `timing:`、`present:`、`av:` 和 `resources:`，并检查固定跳帧追帧、透明边缘、黑边、FPS、截图通知及连续场景切换。只有新的设备结果才能说明实际流畅度变化；主机替身无法证明真实 GE 缓存时序或吞吐表现。

现有显示路径说明见 [游戏画面呈现与滤波](GAME-RENDERING.md)，视频部分见 [MPEG 解码与读取突发优化](MPEG-STUTTER.md)。
