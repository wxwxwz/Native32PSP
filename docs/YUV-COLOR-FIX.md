# YUV 阴影与边角绿点修复

用户报告角色阴影和旗帜边角出现错误绿点。阴影截图取样为 `#009A00`，恰好对应旧转换公式对 `Y=16、U=0、V=0` 的输出：零色度减去 128 后参与计算，得到 RGB `(0,154,0)`，使本应呈黑色的阴影网点变绿。

旧 PSP、Rust、Java 和原 Python 实现沿用了相同处理。此前图像优化与旧实现逐像素一致，只证明优化保留了旧行为，无法发现双方共有的格式解释问题。上游说明也明确提到色度插值尚未完全理解；本次按截图和真实素材对照作兼容修复，不将推断写成已确认的权威格式规则。

## 修复范围

保留原有先纵向、再横向借用相邻色度的顺序。两步完成后，对仍为零的 U、V 分量分别使用中性色度 128；已经找到的非零色度继续原样转换。这样不会提前用中性色度盖掉有效的邻居颜色。

`Y=0` 继续表示透明。上述 `Y=16、U=V=0` 样本变为不透明黑色，阴影保留黑色与透明像素交错的网点结构。这项处理作用于输入色度，不设置绿色色键，也不按最终 RGB 删除绿色；正常的绿色图案应继续显示。

改动位于游戏图像的 YUV 解码路径，保留两行色度缓冲及融合透明边界统计。`0104` 的全部性能诊断与此前 MPEG 优化继续保留。本轮针对颜色正确性，不承诺速度变化。

## 验证与构建

本地独立解析 `BBLADE/BBPLAY10.SSL` 的 1032 张图像，没有解包错误；其中 630 张图的 44465 个有效像素在相邻恢复后仍有零色度，40216 个像素是上述 `Y=16、U=V=0`。蓝发女角色图像 #636（46×74）的 127 个阴影绿点均属于这一情况，原始块含 `Y=[0,16,16,0]、UV=[0,0]`，修复后是黑色／透明交错。该图另有两个 `Y=99` 的剑尖像素由绿变灰。这是解码素材预览核对，还不是真机复测。

真实文件 SHA256 为 `d8cb739d81559cf4031e9e44386b9cfe17aa69da82f3fb5847c624e447844745`；#636 原始图像块 SHA256 为 `1b7147679df2014da7f98b4eb194e9d838fde331f38062c11031e9fb54a9e360`。截图中的旗角尚未定位到具体资源，因此不能据此断言其全部颜色已经恢复。中性色度回退无法推导已经缺失的原始彩色信息，其他素材边缘仍需实际观察。真实游戏资源不随源码或测试包分发，也没有上传到编译服务器。

新增独立 RGB／alpha 预期，覆盖黑色／透明网点、单个色度分量缺失、四个方向邻色优先、奇数尺寸、边界 metadata 和合法绿色。默认参考解码器保留旧行为；差分及解码基准显式选择修复后的参考规则。受影响的像素不再要求与旧规则一致。
